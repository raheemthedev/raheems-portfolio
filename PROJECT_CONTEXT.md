# Raheem Portfolio — Project Context

This file is a handoff for another model or developer continuing the portfolio. Read it before changing the UI or interaction behavior.

## Repository and workflow

- Repository: `https://github.com/raheemthedev/raheems-portfolio`
- Main branch: `main`
- Local preview: `python3 -m http.server 8000 --bind 127.0.0.1`
- Homepage: `http://127.0.0.1:8000/`
- Work page: `http://127.0.0.1:8000/work.html`
- Case-study template: `http://127.0.0.1:8000/case-study.html?project=01`
- Install dependencies: `npm install`
- Compile TypeScript: `npm run build`
- Validate generated JavaScript: `node --check script.js && node --check work.js`
- Validate patches: `git diff --check`

`script.ts` and `work.ts` are the source files. `script.js` and `work.js` are generated by TypeScript and are intentionally committed. Always edit the TypeScript source and run `npm run build` afterward.

Used by the homepage Index hero, the About experience and education lists, and the archive.
- `projects-data.ts` / `projects-data.js` — every project (`archiveProjects`). Loaded by `work.html` and `archive.html`; add new work here.
- `corner-marks.ts` / `corner-marks.js` — the corner marks as snooker, on every page. "Ra" is always home; "he", "e" and "m" are the balls: press one and it steps out of its corner with a cue behind it; point where it should go — the further the pointer from the letter, the harder the shot (up to full power at about 380px; move back in to ease off) — and let go to strike. It rolls with friction, collides with the other letters and rebounds off the screen edges, and one that slows near "Ra" drops into its place in the name (a count shows beside it; all three in and "Raheem" waves and says hi). Run hard into a screen corner — any but the top-left, where the name is made — a letter sinks out of the window and respawns at home. Whatever a rolling letter passes over takes a gentle knock and springs back: text word by word (each word hit is wrapped once in a `.corner-word` inline-block span), and images, buttons and other small blocks whole; the navigation is included. Knocks use the `translate` and `rotate` properties, skipping elements that already use them. Letters left alone return to their corners.
- `site-details.css` — styles for the corner marks, the footer details and the homepage placeholder cards; loaded on every page.
- `footer-wordmark.ts` / `footer-wordmark.js` — how the footer's RAHEEM answers the cursor (moved here from navigation.ts, loaded after it on every page). **dock** (default, Raheem's pick): the letters near the cursor widen while the rest narrow and slide aside, so the word keeps its width and never clips at the ends, eased there and back with no spring or overshoot. **classic**: the original squash wave. A temporary picker in the footer (or `?footer=dock|classic`, remembered under `raheem-footer-mode-v2`) switches between them; reach, lean, echo, taffy, squash, pluck and spotlight were tried and removed.
- `shape.ts` / `shape.js` / `shape.css` — the homepage "What I shape" section (`[data-shape]` in index.html). **reel** (the design, desktop): the section pins and scrolling — or dragging sideways, with a flick that coasts — travels across a horizontal track: an opening card ("Three ways an idea takes shape", with the three chapters listed), the three chapters (01 Identity — Flip; 02 Digital & motion — Electronic Botanica; 03 Campaigns — Flip's launch), and a closing card ("Got an idea worth shaping?" with Start a project ↗ and See all work →). Each chapter has a one-line description of what it covers, its disciplines, and a pill link to its case study (or email); captions name the project and what each frame shows, and light up as their frame reaches the middle of the screen. Each chapter opens with its sentence (with image pills) and details, then four frames at varied sizes and heights that wipe in as they arrive and drift gently at different depths with their images panning inside; the reel travels 1.7× faster than the page scrolls (`reelSpeed`), so it's about six screens of scrolling; the background changes to each chapter's tone (navy, deep violet, lavender). Hovering a frame dims the others; clicking a frame (or a pill) opens it full screen with captions and arrow-key/Esc navigation across all 12. A strip at the foot shows a frame count, progress and chapter buttons. **sentence** (narrow screens, and parked behind `?shape=sentence`): each chapter as one huge sentence whose words ink in on scroll, with pills that preview on hover. Pills scale on hover rather than widen, so the line never reflows under the cursor. Drag scrolling uses instant steps because the page's `scroll-behavior` is smooth. Captions are in the markup.
- `about-intro.ts` / `about-intro.js` / `about-intro.css` — the About page's "A little more about me" section, built from the section's own HTML copy. **desk** (the design): the headline centred with a plus button beneath it, while the three notes (as taped index cards) and two project prints drop onto the desk; they can be picked up, thrown and rearranged. The plus drops a yellow "For Raheem" sticky note (up to four at once; a × in its top-left corner discards it) with a textarea ("Want to know more about Raheem?"), an optional reply email and a Send button; the plus shows "Want to ask Raheem something?" on hover and focus, and once by itself after the desk lands. Notes are POSTed quietly to Raheem's Formspree form (`aboutNoteEndpoint` in about-intro.ts, https://formspree.io/f/moeejevw) with message, optional email and subject; if the endpoint is emptied, Send falls back to opening the visitor's mail app. Once sent, the note shrinks back into the plus it came from (`sendAway`); as it goes in, the circle floods black, the plus turns into a white paper plane that winds back and launches off up and away with a streak, a tick draws in, and the circle settles back to the outlined plus, and a thank-you shows under the plus. (A crumpling-paper version — 2D canvas, then WebGL with three.js — a "Sent" stamp, a peel-off and a fade were tried and removed.) ## Shared visual system

- Primary UI font: Overused Grotesk. Footer wordmark and fixed corner text: Marcellus Regular.
- Landing background: `#f4f4f1`.
- Work page background: `#f4f4f1`, matching the homepage paper background. Its footer remains `#101010`.
- Preserve the fixed corner text: `Ra`, `he`, `e`, `m`. It uses a white `mix-blend-mode: difference` treatment so it automatically inverts against light, dark, image, and tonal backgrounds.
- Preserve the centered navigation and its current context on every page. It is fixed, uses `mix-blend-mode: difference`, and must remain stationary while the page scrolls.
- The navigation and all four permanent corner marks use the maximum interface z-index so they remain above page content and media.
- Keyboard shortcuts mirror the visible menu: `W` opens Work, `A` opens About, and `C` follows the current page's Contact link. Shortcuts must not fire while typing or using modifier keys.
- The UI uses responsive `clamp()` sizing so it remains proportionally useful at browser zoom levels such as 70–80%, not only at 100%.
- Asset query revisions in `index.html` and `work.html` are used to bypass stale localhost/browser caches. Increment the revision after visible CSS or JavaScript changes.

## Homepage state

The homepage contains a horizontal project wheel inside `.project-stage`.

On every homepage load, a full-screen loader begins with a centered Marcellus `Raheem` wordmark on black. The word fractures into `Ra`, `he`, `e`, and `m` around a truly viewport-centered, initially empty paper window. After a short blank-window hold, the window expands; landing content does not begin entering until the expansion is substantially underway. The navigation and landing statement then fade in, the project lens opens vertically, and the four fragments travel to and hand off seamlessly to the permanent corner marks. Preserve the reference sequence in `reference/1.png` and `reference/2.png`, avoid the bottom-heavy positioning shown in `reference/thebug.png`, and keep the motion staged and smooth rather than abrupt.

Current behavior:

- Wheel and drag scrolling with inertia.
- The homepage project rail drifts left at a slow passive pace by default and eases to an almost complete stop while hovered.
- The rail renders four complete project sequences and measures its loop period from real element offsets to prevent an empty interval at the wrap point.
- Passive rail motion does not hide project metadata or trigger the stronger user-scroll inertia treatment; only wheel, drag, and keyboard input do that.
- Subtle cursor-driven gyro/parallax across the landing page and project frames.
- WebGL shader layer retained.
- Project metadata hides while the wheel moves and returns before motion fully settles.
- Frames use an SVG lens mask at the top and bottom.
- No frame-height compression or animated lens compression is present. Do not reintroduce compression unless explicitly requested.
- Project cards are image-ready through optional `image` and `imageAlt` properties in `script.ts`.
- Clicking a homepage rail card opens the matching `case-study.html?project=NN` page; drag gestures are distance-checked so they do not trigger navigation.
- The landing statement, project-frame width/height, metadata, fixed marks, and scroll cue use viewport-relative sizing so they retain their intended physical scale when browser zoom changes.
- A pill CTA follows the landing statement and links to the homepage Featured Work section.
- The homepage Featured Work section uses a black, asymmetric editorial grid based on `reference/nothin home page.png`.
- Project content is still placeholder content.

Important homepage preferences:

- Keep gyro subtle and smooth.
- Avoid cursor-following white highlights or white-light hover effects.
- Avoid excessive sway or heavy scrolling.
- Keep the work wheel responsive and visually centered across zoom and viewport changes.

### Homepage hero variants

- `hero-modes.ts` renders the active variant into `.hero-alt`. The switcher at the bottom right offers **Horizon** (the default) and **Field**; the last choice is kept in `localStorage`.
- Parked but intact, reachable only by URL: `?hero=index`, `?hero=orbit` (the halo of rings) and `?hero=classic` — the original project wheel, whose markup and code in `script.ts` are untouched (`?hero=wheel` also maps to it). `hero-modes.css` hides `.project-stage` unless `body[data-hero="classic"]`, and `renderRail` pauses while it is hidden.
- Horizon (after a reference Raheem gave): every image in the work (the `gallery` arrays in `script.ts`, plus titled tiles for projects still to come) streams right to left as one hairline of tiny thumbnails on the paper background. Through a window in the middle the line opens: images swell to full size, cropped like prints, and scatter above and below it into an overlapping collage that reshuffles as it flows, then shrink back into the line. Scroll or drag scrubs the stream, hovering slows it, clicking an image opens its project.
- Field: an endless 3D depth field inspired by emishovictor.com's Spatial Mode. Tiles are large and laid out in strata so the field is never empty, and the six projects open in a ring around the statement. It drifts toward the viewer; page scroll pushes the camera, drag pans with momentum, the cursor parts nearby tiles and turns them to face it. `Enter space` takes the field full screen (`html.is-hero-immersive`), flown with the wheel, arrows and drag; Esc or `Leave space` returns.
- How you get into the space is picked beside the button (`?entry=edge|dark`, remembered): **edge** (default) — the page tips up and away as the work rushes toward you and you dive in. **dark** — darkness spreads from the button and the tiles glow up one by one.
- The loader reveals whichever hero is active with the same lens opening, and `script.ts` dispatches `hero:reveal` to start each variant's entrance.
- All variants read the shared `projects` array in `script.ts`. Placeholder projects render as titled tiles until artwork exists.
- Once a final hero and entry are chosen, remove the switcher, the entry picker and the parked variants you no longer want.

### Detailed info view

Each row contains:

- Discipline/service pills at the top-left.
- A `See Full Case ↗` action at the top-right. This is currently a placeholder button.

Detailed-gallery behavior:

- Frames are intentionally empty tonal blocks: black, grey, and off-white.
- Rows and frames clip overflow so moving content never spills beyond their boundaries.
- Alternating rows move in opposite directions.
- Galleries use duplicated frame sequences for seamless looping.

- Hovering a frame expands its real flex width only in Detailed info mode.

- Neighbor spacing remains constant and frames must not overlap.
- Frame sizes and the compensating shift use responsive CSS variables, so the interaction continues working at non-100% browser zoom.

## Performance

- Images are served as WebP (made with `cwebp -q 90`, PNG screenshots at `-q 92`, `-sharp_yuv`; only images over 2400px on their long side were scaled down, to 2400). The original JPG/PNG/GIF files are kept beside them but no longer referenced; animated GIFs became animated WebP (`gif2webp -q 90 -mixed`). `assets/projects/electronic-botanica/p13.webp` is an animated WebP left as it was. To add an image, convert it the same way and reference the `.webp`.
- Images in the HTML load lazily (`loading="lazy" decoding="async"`) unless marked otherwise.
- The corner marks' animation loop sleeps when nothing is moving and wakes on a press, a shot or a resize.
- Vercel's build runs `npm run build && npm run minify`: `scripts/minify.mjs` minifies the JS and CSS in place with esbuild, as plain scripts so the globals shared between files keep their names. The repository's own `.js`/`.css` stay readable; don't run `npm run minify` locally.
